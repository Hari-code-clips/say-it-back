# Privacy data flow: every personal-data element, source to deletion (17 Oct 2026)

A DPIA-lite for the judging deployment (review P1-4): device mode (no accounts), `DATA_REGION=in`, `SIB_KEEP_AUDIO=false`, `SIB_REQUIRE_CONSENT=true`, `SIB_RETENTION_DAYS=90`, the demo permit stub on `SIB_WEBHOOK_URL`. Where each model and store runs is in `docs/ARCHITECTURE.md`, "Data regions"; this page follows each piece of personal data through them. It describes the code as it is; it is not a legal assessment, and it claims no compliance. The worker-facing and supervisor-facing wording is the app's `/privacy` page (`web/src/i18n/en/privacy.ts`).

What is never collected: a worker's name, ID number, nationality, photo, score or history. A record is about one answer to one briefing, not about a person; the supervisor's optional `by` on a decision is the only free-text field that can name someone, and it is the supervisor's own entry.

"Flash (global)" below is Gemini 3.8 Flash on Agent Platform's `global` endpoint, which does not fix where a request is processed; "Live (US)" is Gemini 3.8 Live in `us-central1`. Both are outside Singapore and India.

## The elements

| Element | Source | Processors (where) | Storage | Retention | Deletion path |
|---|---|---|---|---|---|
| **Worker's voice** (answer audio, 16 kHz WAV) | the phone's microphone, only inside an answer window and only after the worker chose "I agree" (`consent.py`; with stored sample answers no voice is recorded and no consent screen is shown) | the phone; the backend on Cloud Run (`REGION`), in memory; live mode: streamed through the backend to **Live (US)**; the check: the clips go to **Flash (global)**, to the blind transcriber and judge A (judge B never gets audio) | the phone's IndexedDB upload queue until the check answers (`web/src/net/queue.ts`); on the server nowhere: ADK sessions are in memory and the clips are dropped after the check | phone: until the check answers, at most 24 h (`MAX_AGE_MS`); server: the request's lifetime | automatic on both. `SIB_KEEP_AUDIO=true` (consented volunteers only, off in deployment) writes the clips under the data directory, and `DELETE /api/briefings/{id}` removes them |
| **Transcript** (verbatim, in the worker's language; and the verbatim quotes in the ratings) | the blind transcriber's output; in live mode also what Live heard (`round.live.heard`) | **Flash (global)** writes it; judges A and B read it (B on Flash-Lite, global); **Live (US)** writes `heard` | Firestore `briefings/{id}` in `REGION`: `round.transcripts[].original`, the ratings' `quote`, both judges' passes, `round.live.heard`; digests of them in the record chain | `SIB_RETENTION_DAYS` (90) from the record's creation: `expireAt`, then the Firestore TTL policy deletes it within about a day; read as gone from `expireAt` on | `DELETE /api/briefings/{id}` (Record screen, "Delete this record") at once, or the TTL. Never sent in a webhook; analytics rows are redacted |
| **Translation** (the transcript and quotes in the supervisor's language) | the transcriber, beside the transcript | **Flash (global)** | Firestore, `round.transcripts[].translation` and the ratings' `quoteTranslation` | as the transcript | as the transcript |
| **Hazard report** (the worker's problem button) | the phone: a short recording, or a tap with no audio; the supervisor's acknowledgement note | the backend in memory; the `hazard_report` agent on **Flash (global)** transcribes verbatim and translates; the audio is dropped after it | Firestore, `briefing.hazards[]`: `original`, `translation`, `kind`, the acknowledgement's note | as the record | with the record (delete or TTL). Webhooks carry only its id, kind and whether it was acknowledged |
| **Decision reason** (and the optional `by`) | typed by the supervisor; Go with an open step needs a reason | the backend; then every webhook | Firestore, `briefing.decision`; a digest in the record chain; copies at each webhook receiver: the JSON record (`decision`, reason included) to the permit-to-work system (the reference stub never stores the reason, so no route of its can show it, and keeps `by` in its own record, never shown or served; a real e-permit system keeps what its own rules say, and a field map can leave both out), and the Google Chat text ("Reason:", "By:") | ours: as the record; a receiver's copy: that system's own retention | ours: delete or TTL. A copy already sent belongs to the receiver and is deleted there (the delete dialog says so) |
| **Device key hash** | the browser makes a random device key and keeps it in `localStorage`; it is sent as `X-SIB-Device` on every request | the backend hashes it (SHA-256, `caller.owner_hash`) and scopes every read and write to the hash | Firestore: the `owner` beside each briefing; the name of the device's SOP library document (a SHA-256 of the site and the owner hash); the idempotency keys of check uploads (a SHA-256 that includes it). The key itself is never stored server-side and never logged (tested) | the briefing's `owner` goes with the record; library and idempotency documents are never deleted (an idempotency record stops counting at its `expiresAt`, but no TTL policy removes it: step 1 sets TTL on `briefings` and `outbox` only) | with the record for `owner`. Clearing the browser's storage orphans the hash: nothing links it to a person, and no API lists or deletes a library document |
| **Address hash** (the client's IP address) | the request; `X-Forwarded-For` read `SIB_TRUSTED_PROXY_HOPS` from the right (`ratelimit.client_ip`; an IPv6 address stands for its /64) | the backend: per-minute limits and open-socket counts in memory per instance; the daily cap hashes it | Firestore `gemini_calls_ip/{SHA-256 of the UTC day and the address}`, holding only a count; Cloud Run's own platform request logs keep the caller's address (Google's, not the app's lines) | the counter document has **no expiry**; memory: forgotten when idle (at most 10,000 addresses per instance); platform request logs: Cloud Logging's retention for the project | none in the app today (see Open issues). A SHA-256 of an IPv4 address and a date can be reversed by trying every address, so it is a pseudonym, not anonymous |

Also personal data, outside the seven above:

- **The supervisor's instruction** (typed, or dictated: the dictation audio goes to Flash (global) through `transcribe_instruction` and is not kept) is stored as `briefing.instruction`, and kept and deleted with the record. The browser keeps a draft in `sessionStorage` until the briefing exists.
- **The worker's consent choice** (`round.consent`: given or not, and when) is stored with the record and in its chain; it names no one.
- **Volunteer recordings for the eval set** (`eval/record_clips.py`, none yet): a consented volunteer's voice, stored under a speaker code (never a name) in `eval/testset/audio/recorded/`, which is in the public repository and in the backend image's Sample page. `--forget <speaker>` deletes that speaker's clips and items; copies already pushed or deployed must be removed there too.

## Transfers and the two laws

Every model call leaves Singapore and India (Flash, Flash-Lite and TTS on `global`, Live in `us-central1`). Singapore's PDPA (section 26) allows that when the recipient is bound to a comparable standard of protection, for example by contract; it does not require data to stay in Singapore. India's DPDP Act (section 16, Rule 15) restricts transfers only to countries the Central Government notifies, from about May 2027. A site deploying Say It Back covers these transfers, its contract with Google (the Cloud Data Processing Addendum) and its own notice in its own review. Sources are listed under the data-region table in `docs/ARCHITECTURE.md`.

## Open issues (found while writing this, not fixed here)

1. `gemini_calls_ip` and `gemini_calls` documents have no `expireAt`, so the daily address counts are kept until someone deletes them. A TTL policy on a day-stamped field (or a scheduled sweep) would bound them to a day or two.
2. The SOP library and idempotency-key (`check_keys`) documents are never deleted either; they hold no answer content, but they are keyed by the device hash. A TTL policy on `check_keys.expiresAt` would remove the second, once that field is written as a Timestamp (today it is an ISO string, which TTL ignores).
3. BigQuery, when switched on: the dataset is created in `REGION`, but the backend's `SIB_BQ_LOCATION` defaults to `US` and `deploy/02` does not set it.
4. Cloud Run's platform request logs record the caller's address with Cloud Logging's default retention; the app cannot redact them. A log exclusion or a shorter bucket retention would.
5. A real e-permit system or Chat space keeps its copy of the decision reason under its own rules; the delete dialog says so, but nothing propagates a deletion.
